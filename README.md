# snapbak — 增量备份目录库

`snapbak` 是一个 Go 库，为上层备份与恢复流程提供单端点、单序列的
增量快照目录管理。目录元数据保存在进程内存中，文件内容由上游保管，
本库不读取或存储文件内容。

## 特性

- 初始目录为空，快照编号从 0 连续递增（0 为初始空目录）。
- 每个新快照基于最新快照，按输入顺序应用一批变更，整批生效后
  产生不可修改的新版本。
- 只记录普通文件，目录由文件路径隐含，不记录空目录。
- 快照间通过不可变目录树的结构共享存储，删除、文件与目录互换、
  淘汰旧快照都不会改变任何保留快照的内容。

## 变更语义

- `OpWrite path`：写入文件。替换同路径旧文件，清除该路径下全部
  后代文件；若任一祖先路径原本是文件，该祖先文件也被移除。
- `OpDelete path`：删除路径。移除同路径文件及全部后代文件；
  路径不存在时不产生变化。删除 `a` 不影响 `ab`。

## API

```go
s := snapbak.NewStore()

id1 := s.CreateSnapshot([]snapbak.Change{
    {Op: snapbak.OpWrite, Path: "a/x"},
    {Op: snapbak.OpWrite, Path: "b/y"},
})
id2 := s.CreateSnapshot([]snapbak.Change{
    {Op: snapbak.OpDelete, Path: "a"},
    {Op: snapbak.OpWrite, Path: "a/z"},
})

// 查询：路径是文件时返回该文件，否则返回该目录下全部后代文件；
// 空路径查询根目录。结果按字典序排序。
files, err := s.Query(id2, "")   // ["a/z" "b/y"]
files, err = s.Query(id1, "a")   // ["a/x"]，旧快照不受后续修改影响

// 只保留最近 2 个快照；更旧的立即不可查询（返回 ErrSnapshotDropped），
// 仍可基于最新快照继续创建增量版本。
s.Retain(2)
```

路径约定：相对路径，以斜杠分隔，不含空分量、`.` 或 `..`，
区分大小写（由上游保证已规范化）。

## 测试

```sh
go test ./...
```

覆盖场景：目录与文件互换后旧后代不复活、批内变更严格按序生效、
删除的前缀边界、淘汰初始完整快照后继续增量写入删除并与逐快照
完整重建的参考实现比对一致、随机操作对照测试。
